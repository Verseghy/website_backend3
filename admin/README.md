# backend3 admin

The Hungarian-only admin UI of website_backend3: a React single-page app built
on [ra-core](https://marmelab.com/ra-core/) and
[shadcn-admin-kit](https://marmelab.com/shadcn-admin-kit/), served by backend3
at `/admin` from `admin/dist` (ADR 0004). It is licensed `AGPL-3.0-only`, like
the rest of the repository; the copied kit and shadcn/ui files keep their MIT
licences (see `../THIRD_PARTY.md`).

| Path | What it is |
|---|---|
| `src/main.tsx` | composition root: the only place that reads the build environment |
| `src/App.tsx`, `src/router.tsx` | the `<Admin>` root and its browser-history router under `/admin` |
| `src/i18n/` | `hu.ts`, the single message file, and the provider (ADR 0021) |
| `src/auth/` | the auth provider, the only client of `/api/admin/auth`, the Hungarian sign-in screen and the sign-out hook (ADR 0006) |
| `src/api/` | helpers shared by the auth and data providers: the same-origin API base path and the error-envelope reader (ADR 0021 §4) |
| `src/data-provider/` | backend3's own ra-core data provider, and the generic reads of every resource over the shared admin list contract (`list-handlers.ts`, `list-contract.ts`) |
| `src/resources/` | the resources' screens, one directory each (so far `labels/`, the „Címkék” list), `ResourceList`, the list page every resource uses, and `handlers.ts`, every resource's data-provider handlers |
| `src/update-prompt/` | the reload prompt after a deploy (ADR 0004 §5) |
| `src/source-link/`, `src/about/`, `src/layout/` | the AGPL source link, the about page and the footer (ADR 0012 §4), and the header's user menu with „Kijelentkezés” (ADR 0006 §2) |
| `src/recorder/` | the development-only clipboard recorder for paste fixtures (editor.md §13.1); not in the default build |
| `src/bindings/` | TypeScript types generated by ts-rs from the Rust DTOs; never edited (ADR 0005) |
| `src/components/admin/`, `src/components/ui/` | vendored shadcn-admin-kit and shadcn/ui code, with `LICENSE` and `LOCAL_CHANGES.md` |
| `e2e/` | Playwright tests against a running backend3, with the seed values they expect (`seed-account.ts`, `seed-labels.ts`) |
| `eslint-rules/` | the `local/no-ui-literals` rule (ADR 0021 §7) |
| `scripts/`, `license-policy.json` | the production-dependency licence check (ADR 0022 §4), the Vite plugin that completes the licence notices of the bundled packages and copied code, `dist/licenses.txt` (ADR 0038), and the clean-room check that no `@react-admin/` (Enterprise) package is named (ADR 0011 §8, ADR 0018 §3.4) |

Commands, rules and the gate are in `CLAUDE.md`. In short: `npm ci`, then
`npm run dev` (Vite on port 5173, proxying `/api` and `/storage` to a local
backend3 on port 5150), `npm run lint`, `npm run typecheck`, `npm test`,
`npm run licenses`, `npm run clean-room`, `npm run build` and `npm run e2e`.
The E2E tests sign in with the seed account (`../AGENTS.md`, "The seed
account"), which `LOCO_ENV=e2e cargo loco db seed` creates.

## The clipboard recorder

The „Vágólap-rögzítő” at `/admin/clipboard-recorder` turns a paste into a
JSON capture file for the paste tests (editor.md §13.1, §13.2): the clipboard
`types`, the `text/html` and `text/plain` data with user folder names
scrubbed, and each file's type and size, never RTF or file bytes. It is a
development tool. `npm run dev` always has it, a build has it only with
`VITE_CLIPBOARD_RECORDER=1 npm run build`, and the image build, which the
Containerfile pins to `VITE_CLIPBOARD_RECORDER=0`, leaves out its route and
code. Paste only synthetic documents, and review each capture for names
before committing it.
